## 1. Objective
TriAttendance is an enterprise-grade attendance and compliance web portal designed for Account Managers to oversee location-verified employee check-ins across multiple operational sites.

The portal provides real-time verification of GPS geofencing, selfie captures, and blink-liveness proofs generated by field employees on their mobile devices. It empowers Account Managers to monitor team presence, inspect exceptions (out-of-boundary check-ins, failed liveness, missing check-outs), escalate infractions to supervisors, and export audit-ready compliance records, while enforcing strict server-side multi-tenant scoping and zero mutation permissions on raw attendance logs.

## 5. Code Style

Strict TypeScript with explicit typing, shared Zod schemas for contract validation, Drizzle ORM for type-safe database queries, and raw PostGIS SQL where spatial functions are executed.

### Representative Code Snippet: PostGIS Geofence Evaluation & Scoping Service

```typescript
// apps/api/src/modules/attendance/attendance.service.ts
import { Injectable, ForbiddenException, NotFoundException } from '@nestjs/common';
import { sql } from 'drizzle-orm';
import { db } from '../../database/drizzle.client';
import { locations, attendanceRecords, auditLogs } from '../../database/schema';
import { CheckInRequestDto, CheckInResult } from '@triattendance/shared';

@Injectable()
export class AttendanceService {
  /**
   * Evaluates employee check-in against assigned location geofence using PostGIS.
   * Enforces server-side spatial calculation and records immutable audit trail.
   */
  async processCheckIn(dto: CheckInRequestDto): Promise<CheckInResult> {
    // 1. Fetch assigned location and compute distance in meters using PostGIS ST_Distance
    const [targetLocation] = await db
      .select({
        id: locations.id,
        name: locations.name,
        radiusMeters: locations.radiusMeters,
        distanceMeters: sql<number>`
          ST_Distance(
            ${locations.geog},
            ST_SetSRID(ST_MakePoint(${dto.longitude}, ${dto.latitude}), 4326)::geography
          )
        `.as('distance_meters'),
        isInside: sql<boolean>`
          ST_DWithin(
            ${locations.geog},
            ST_SetSRID(ST_MakePoint(${dto.longitude}, ${dto.latitude}), 4326)::geography,
            ${locations.radiusMeters}
          )
        `.as('is_inside'),
      })
      .from(locations)
      .where(sql`${locations.id} = ${dto.assignedLocationId}`);

    if (!targetLocation) {
      throw new NotFoundException(`Assigned location #${dto.assignedLocationId} not found.`);
    }

    // 2. Validate mock location, GPS accuracy, and spatial boundary
    const isMock = dto.isMockLocation === true;
    const isDistanceViolated = !targetLocation.isInside;
    const isLivenessFailed = !dto.livenessPassed;

    let computedStatus: 'Present' | 'Late' | 'Rejected' | 'Flagged' = 'Present';

    // Site late cutoff rule: 09:30 in Asia/Kolkata timezone
    const checkInTimeIST = new Date(dto.timestampUtc).toLocaleTimeString('en-US', {
      timeZone: 'Asia/Kolkata',
      hour12: false,
      hour: '2-digit',
      minute: '2-digit',
    });

    if (isMock || isDistanceViolated) {
      computedStatus = 'Rejected';
    } else if (isLivenessFailed) {
      computedStatus = 'Flagged';
    } else if (checkInTimeIST > '09:30') {
      computedStatus = 'Late';
    }

    // 3. Persist attendance record (read-only for managers)
    const [record] = await db
      .insert(attendanceRecords)
      .values({
        employeeId: dto.employeeId,
        locationId: targetLocation.id,
        checkInTime: new Date(dto.timestampUtc),
        latitude: dto.latitude,
        longitude: dto.longitude,
        gpsAccuracyMeters: dto.gpsAccuracyMeters,
        isMockLocation: isMock,
        selfieUrl: dto.selfieStorageKey,
        livenessPassed: dto.livenessPassed,
        distanceFromBoundaryMeters: Math.max(0, targetLocation.distanceMeters - targetLocation.radiusMeters),
        status: computedStatus,
      })
      .returning();

    // 4. Record audit log entry
    await db.insert(auditLogs).values({
      actorId: dto.employeeId,
      actorType: 'EMPLOYEE_DEVICE',
      action: 'CHECK_IN_RECORDED',
      details: {
        recordId: record.id,
        distanceMeters: targetLocation.distanceMeters,
        status: computedStatus,
      },
      createdAt: new Date(),
    });

    return {
      recordId: record.id,
      status: computedStatus,
      distanceMeters: targetLocation.distanceMeters,
      isInsideGeofence: targetLocation.isInside,
    };
  }
}
```

## 8. Success Criteria

1. **Geospatial Accuracy:** Check-in coordinates at 1.4 km outside a 500 m geofence (as in `AM 07`) are evaluated by PostGIS `ST_DWithin` as `false`, and `ST_Distance` calculates distance with < 1 meter discrepancy from reference coordinates.
2. **Server-Side Data Scoping:** An Account Manager assigned to `CHN-1` querying the API with `locationId=BLR-3` receives `403 Forbidden` or an empty scoped dataset, even if valid IDs are manipulated in frontend requests.
3. **Immutability of Attendance Records:** Neither the web UI nor the backend API provides any `PATCH`/`PUT`/`DELETE` endpoints for Account Managers on `attendance_records`.
4. **Authentication & Brute Force Lockout:** 5 consecutive failed login attempts on an email address trigger a 15-minute account lockout, returning `429 Too Many Requests` or `401 Unauthorized (Account Locked)` with audit logging.
5. **Exception Escalation Workflow:** Submitting a rejection note ("Client visit at Guindy — confirmed by phone") and clicking "Escalate to Supervisor" records a supervisor escalation task in the database, sends an email notification via SMTP, and creates an append-only audit log entry.
6. **Reporting Engine:** The Records download page calculates estimated row count (e.g. 1,340 rows across 2 locations) within < 200 ms; triggering a download enqueues a BullMQ job that yields streaming CSV or Playwright-rendered PDF archived to object storage and listed in "Recent downloads".
7. **Accessibility & Design Token Fidelity:** All 9 reference screens match the Figma purple/indigo color tokens, badge outlines, and typography; automated `@axe-core/playwright` audits report zero critical/serious accessibility violations.
